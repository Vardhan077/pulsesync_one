# PulseSync AI – architecture upgrade

This revision aligns the implementation with the agreed workflow:

Audio -> real transcription -> automatic diarization/identification -> transcript review -> company -> playbook -> AI generation -> review/evidence -> CRM sync.

Key changes:
- Speaker mapping is no longer a mandatory workflow step. Speaker identities appear inline on the transcript; only uncertain speakers need correction.
- No synthetic customer/company/competitor/budget/sample meeting data is generated by fallback paths.
- AI extraction is grounded to the current meeting transcript and validated evidence IDs.
- Missing fields remain null / Not mentioned instead of being inferred from unrelated sessions.
- Call type remains first-class metadata and can be AI-classified or manually overridden.
- Processing stays in a dedicated loading state until transcript processing completes; the UI polls and notifies when ready.
- Company linking is explicit; the frontend no longer guesses company names from filenames/titles.
- CRM sync remains downstream of review/approval.
- Fallback JSON storage starts empty to prevent stale demo data from contaminating tests.

## Run

1. Root: `npm install`
2. AI service: `python -m pip install -r ai-service/requirements.txt`
3. Configure `.env` and `ai-service/.env`.
4. Start AI service: `uvicorn main:app --reload --port 8000` from `ai-service/`.
5. Start dashboard/backend: `npm run dev` from root.
6. Load `extension/` as an unpacked Chrome extension if extension capture is being tested.

## Important

Automatic acoustic speaker diarization requires a real diarization provider. The code no longer fabricates speaker assignments when one is unavailable. If `pyannote.audio` is configured, the local ML path can provide acoustic diarization; otherwise configure a production diarization service before expecting named speaker attribution.
